# 📖 novel-model-benchmark · 中文小说模型对比测试

在一个**免费的云 GPU**（ModelScope 魔搭社区 · NVIDIA A10 24GB）上，用同一段剧情分别测试两个 27B 中文小说模型，看谁写的正文更好，并把结果自动保存成文件。

**你不需要懂 Linux、Python、CUDA 或任何模型部署知识。** 整个过程只需要：注册账号 → 点一个链接 → 选 GPU → 点"运行全部" → 粘贴剧情 → 看正文。

| 测试对象 | 运行方式 | 首次下载 | A10 24GB 显卡 |
|---|---|---|---|
| ① WebNovel Writer（西幻·白描风） | llama.cpp + Q4_K_M 量化 | ≈16.5GB | ✅ 推荐，稳定运行 |
| ② 玄幻 DPO（结构化大纲→正文） | 4bit 底模 + LoRA 适配器 | ≈23.4GB | ⚠️ 尝试性支持（见 FAQ） |

> 本项目只做**小规模推理对比测试**，不包含模型训练、微调、Web 服务或 Docker。
> 本项目与 wcn123、JiangLing-js、unsloth、ModelScope 均无隶属关系。

## 🚀 完整使用流程（七步）

### 第 1 步 · 注册 ModelScope（约 5 分钟）

1. 打开 [https://www.modelscope.cn](https://www.modelscope.cn)，点右上角**注册**（手机号即可）；
2. 按提示完成**实名认证**（免费 GPU 需要实名，一次性操作）；
3. 普通用户有 **36 小时免费 GPU 时长**（按开机时间计），CPU 实例不限时。时长在网页右上角「我的Notebook」里可以看到。

### 第 2 步 · 打开本项目的 Notebook 映射链接

在浏览器打开下面这个链接（已填好本仓库地址，直接点或复制到浏览器）：

```
https://modelscope.cn/notebook/share/github/florent0921-lgtm/model-deploy/blob/main/modelscope_test.ipynb
```

打开后点页面右上角的 **「在 Notebook 中打开」**，ModelScope 会自动把这个 GitHub 仓库的 Notebook 映射成一个云端环境。

> 如果你用的是自己 Fork / 复制的仓库，请把链接中的 `florent0921-lgtm/model-deploy` 换成你自己的 `用户名/仓库名`。

> **打不开映射链接时的备用方法（效果一样）：**
> 1. 在 ModelScope 网页进入「我的Notebook」→「启动 Notebook」→ 选 GPU 镜像启动；
> 2. 打开左侧文件管理器，把本项目下载的 `modelscope_test.ipynb` **直接拖进去上传**（右键 → Open 打开）；
> 3. Notebook 首次使用批量盲评等功能时会自动创建 `prompts/` 示例文件，无需手动上传。

### 第 3 步 · 选择 A10 GPU 并启动

创建环境时：

- **环境/镜像**：选任意带 GPU 的镜像（推荐 PyTorch + CUDA 类）；
- **GPU 规格**：选 **NVIDIA A10 · 24GB 显存**（免费）；
- 点**启动**，等待 2~5 分钟进入 Notebook 页面。

### 第 4 步 · 运行全部

打开 `modelscope_test.ipynb`，点菜单 **Run → Run All Cells（运行全部）**，然后看屏幕提示即可：

- 前几步会自动完成：环境自检 → 装依赖 → 准备下载工具（几分钟）；
- 到「第 5 步」会**自动下载并加载默认模型①**：首次约 16.5GB，视网速 10~40 分钟（有进度条；中断了重新运行会**断点续传**，不会重头下）。模型保存在 `/mnt/workspace/models`（100GB 持久盘），**以后再也不用重新下载**；
- 如果 Hugging Face 官方下载源连不上，程序会**自动切换第三方镜像 hf-mirror.com** 继续下载，不需要你操作。

### 第 5 步 · 粘贴剧情提示词，生成正文

到「第 6 步」的输入框：

1. 把你的剧情粘贴进去（骨架、场景描述、待润色正文都行；不知道写什么就先用示例）；
2. 模型①可在「任务类型」里选：**骨架扩写 / 场景扩写 / 正文增强 / 正文润色**（都是模型作者官方提供的输入格式，程序会自动套模板）；
3. 点 **【✍️ 开始生成】**，正文会逐字显示（约 1~5 分钟，目标 500~1000 字）。

### 第 6 步 · 查看与保存结果

- 正文直接显示在屏幕上；
- 同时**自动保存**两个文件到 `/mnt/workspace/novel-model-benchmark/results/`：
  - `模型名_日期时间_测试编号.txt` —— 纯正文；
  - 同名 `.md` —— 附带生成参数、耗时、显存等记录（方便日后对比）；
- **下载到本地**：在 Notebook 左侧文件列表找到文件 → 右键 → **Download**。

想测第二个模型：回「第 5 步」，下拉框选 ② → 点【加载 / 切换模型】（首次另下载约 23.4GB）→ 回「第 6 步」粘贴**同一段剧情**再生成，即可对比。

### 第 7 步 · 关闭 GPU（省时长）

用完后：ModelScope 网页 →「我的Notebook」→ 对应实例 → **停止**。

- 时长只按**开机时间**扣，停止后不扣；
- `/mnt/workspace` 里的模型和结果**全部保留**，下次启动直接复用；
- 只有**删除实例**才会清空文件，删除前记得把 `results/` 下载到本地。

## 🧪 批量盲评模式（可选）

想系统地对比两个模型，而不是每次手贴一段剧情：

1. 把多条测试剧情放进 `prompts/` 文件夹（一个 `.txt` 一条，首次运行会自动生成 3 个示例）；
2. 打开 Notebook「第 8 步」，把 `BATCH_MODELS = []` 改成 `["webnovel", "xuanhuan"]`，重新运行该 Cell；
3. 程序会用两个模型各跑一遍全部剧情，结果保存在 `results/anonymous/`，文件名**隐藏模型名**（`sample_001_A.txt`、`sample_001_B.txt`…）；
4. A/B 与真实模型的对照表在同目录 `AAA_评分后再看_对照表.txt` 里——**评分之前别打开**，先盲读正文打分，再看对照表，结论才客观。

## ❓ 常见问题

**Q0：下载模型也会消耗我的免费额度吗？怎么省？**
会。GPU 免费时长（普通用户 36 小时，以 ModelScope 页面实时显示为准）按**开机时间**计——从实例启动到停止，期间不管 GPU 在不在计算、包括下载模型，都在计时。下载 16.5GB 视网速约 10~40 分钟（云端机房内网通常快得多）。两个省额度的办法：

1. **CPU 预下载（Notebook 已内置）**：ModelScope 的 CPU 实例免费且不限时。先在 CPU 实例上运行本 Notebook，它会自动检测并进入「预下载模式」——只下载两个模型、不加载不生成；完成后停止 CPU 实例、启动 GPU 实例重新运行，模型从持久盘秒加载。整个下载过程**不占 1 分钟 GPU 时长**。
2. **平时保持停止状态**：模型下载后永久保存在 `/mnt/workspace`（100GB 持久盘），下次开机**不会重新下载**，每次开机只需 1~3 分钟把模型加载进显存。用完就停止实例，只在生成时开机。

以纯推理测试的强度，36 小时非常充裕：一次完整会话（下载 + 生成几段正文）通常在 1 小时以内。

**Q1：模型②到底是什么意思的"尝试性支持"？**
模型②的 4bit 底模有 22.3GB，而 A10 整卡只有 24GB——放完权重几乎没有余量。程序会先尝试纯 GPU 加载；失败则自动做**唯一一次**降级尝试（降低上下文 + 把少部分层放到内存）；如果还是失败或速度过慢，会直接提示"建议改用 80GB 显存的 GPU 实例测试模型②"。这是模型体积的物理限制，**不是你的操作问题，也不需要你排查**；模型①不受任何影响。

**Q2：下载中断/报网络错误怎么办？**
重新运行对应的 Cell 即可，下载支持**断点续传**，会从断掉的地方继续。程序会自动在 Hugging Face 官方源和第三方镜像 `hf-mirror.com` 之间切换（镜像是第三方维护的非官方节点，仅用于下载公共模型文件，不涉及账号令牌）。

**Q3：生成太慢？**
模型①在 A10 上通常 1~5 分钟能出一篇 500~1000 字正文。如果明显过慢，运行「显存随时查看」那个 Cell，确认模型加载进了 GPU（正常应占用 17GB 以上）。

**Q4：能改生成参数吗？**
能，而且只需要改一处：Notebook「第 1 步」的配置 Cell 里集中了所有模型 ID 和参数（默认值均来自模型作者的官方说明）。改完从第 1 步开始重新运行即可。

**Q5：免费时长用完了怎么办？**
GPU 时长（36 小时）用完后可以改用 CPU 实例不限时使用，但两个 27B 模型在 CPU 上生成极慢，仅适合整理/下载 `results/` 里的文件。
